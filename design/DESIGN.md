# 設計 v1：求人LP量産システム（recruit-factory）

v0 を、他のAI 3体（求人マーケ／法務／量産技術）の反論で直した版です。反論ごとの採否は [REVIEW.md](REVIEW.md)。

## なぜ
- 加盟店はそれぞれの地域で、業務委託の職人を集める必要がある
- タスカルの求人LPは「面談で話すことを先に全部出す」型で信頼をつくれている
- この型を手作業で60社分作ると、品質がばらつき、古い数字や法的に危ない表現が残る
- だから **事実を1枚埋めれば、同じ品質・同じ安全さで出せる** 仕組みにする

## 何を作るか

### 原則（v1）
1. **正本は `sites/<slug>/data.yml` 1枚**。HTMLは毎日自動で作り直す生成物
2. **事実がない欄は作文で埋めない**。代わりに「店→グループ」の順で事実を探し、出所ラベルをつけて載せる
3. **古い数字は自動で隠す**。確認日から60日（募集枠は30日）で非表示、オーナー承認から60日で「停止モード」（noindex・求人構造化データを外す）
4. **危ないものは公開させない**（ビルドを止める）
   - リース・業者紹介・紹介料・購入条件がある → 特商法の確認記録がないと公開不可
   - 研修が契約の前 → 公開不可
   - 支払いが60日超 → 公開不可
   - 雇用の言葉（給与・勤務・シフト・入社・手取り・面接・採用など）→ 公開不可
   - 他店の声を自店の声として載せる → 公開不可

### 構成（v0から変更：1社1リポジトリ → 1リポジトリに全社）
```
recruit-factory/
├─ generator/   build.py（生成と検査）・style.css・terms.yml（NG語辞書）
├─ prompts/     P1ヒアリング・P2生成公開・P3検品
├─ sites/
│  ├─ sample/   架空サンプル（data.yml・images/）
│  └─ <slug>/   各社（data.yml・images/）
├─ design/      分析・設計・壁打ち記録
└─ .github/workflows/build-deploy.yml（変更時＋毎朝6時に全社ビルド→Pages公開）
```
公開URL：`https://miumiumiu4.github.io/recruit-factory/<slug>/`（独自ドメインに切り替え予定）

オーナーはGitHubを触らない。本部がP1でヒアリング→P2でClaude Codeが作成→プレビューURLをLINEで送り「OK」で承認。

### ページ構成
ヒーロー（単価の幅・即契約ではない）→ 01仕事と需要の波 → 02応募資格 → 03募集の背景（出所つき実績）→ 04報酬（計算式・**働き方3択の試算**・根拠のそろった実例のみ）→ 05活動エリア → 06 1日の流れ → 07契約と費用（**初期費用まとめ表＋何件で回収できるか**・向かない人）→ 08応募〜独り立ち（**面談→契約→研修**）→ 09研修（保険・時期）→ 10その先（独立費用の扱い）→ 11FAQ → 12声（同意済みのみ）→ 13代表 → 申込（即時予約リンク）→ **募集を行う事業者**（正式名称・番地・報酬・確認日・ページ制作は本部）

### 地域版
地元の事実（在籍職人数・直近90日の依頼件数・集合場所など）が **3つ以上** ある地域だけ実ページを作る（1社0〜5ページが目安）。それ以外はトップのエリア一覧に文字で載せる。

### 検索
- 求人構造化データ（JobPosting）：employmentType=CONTRACTOR、validThrough=承認日+60日、baseSalaryは出さない（歩合の見積もりは実額ではないため）
- canonical・sitemap（indexさせるページだけ）・noindex（サンプル・停止中・確認前）

### 計測（KPI）
- 段ごとの離脱：ページ閲覧 → CTAクリック（GA4 `cta_click`）→ フォーム送信
- 応募 → 最初の連絡までの時間、面談実施率、面談すっぽかし率
- 契約率、研修完了率、90日後も稼働している率
- 辞退理由の分類（費用・車・収入・時間・条件の誤解）＝ミスマッチ率
- フォームURLに `co`（会社）・`area`・`utm_*` を自動で引き継ぐ。小さな店は件数が少ないので全店まとめて月1回判断

## どうやって
- Python 3 ＋ PyYAML だけ。GitHub Actions で毎日ビルド→GitHub Pages
- 新しい会社：P1（ヒアリング）→ P2（生成・PR）→ P3（検品）→ オーナー承認 → noindex解除

## 今すぐアクション（本部）
1. **弁護士に2点だけ先に確認**：道具・リース・業者紹介の扱い（業務提供誘引販売取引に当たるか）、研修を契約後にする形
2. 独自ドメインを決める（github.io で育てた評価は後から移せないため）
3. 1社目（例：タスカルさん）でP1ヒアリングを実施
4. 面談の申込フォームを4項目＋即時予約にする（フォーム側の改修）
